One Payment. Three Emails.
Why Did That Happen?

Maya paid $120 once. Her bank shows one transaction, but three order confirmations arrive. Follow the webhook and see exactly how the Inbox + State Guard + Outbox design protects her.

A single payment charge is assumed in every scenario. Email/shipments are logical intents, not guaranteed physical deliveries.

4 · The three protections

Inbox: remembers `(provider,event_id)` durably so the same delivery does not become new work.

State guard: changes `PENDING → SUCCEEDED` once, even if a different event ID describes the same payment.

Outbox: saves one business intent in the same DB transaction, then workers retry safely with their own stable idempotency keys.
