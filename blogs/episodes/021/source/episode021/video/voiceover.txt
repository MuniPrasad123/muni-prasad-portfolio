A shopper cancels after paying. Why did the warehouse still ship the order? The old consumer reads loosely typed status strings. A new event slips through a permissive default. Java twenty-one records validate event data. Sealed interfaces define exactly which event types exist. An exhaustive switch forces each event variant to be handled when the application is rebuilt. But compile-time safety is not distributed safety. Guard state changes with PostgreSQL versions and a transactional outbox. Kafka consumers deduplicate and reject stale transitions. The customer sees cancellation pending until refund and fulfillment are resolved.
