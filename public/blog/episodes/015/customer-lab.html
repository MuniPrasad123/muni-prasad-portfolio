    What this model proves—and what it does not

    The state model demonstrates durable-design invariants conceptually. The browser stores no durable inbox, connects to no provider and cannot prove transaction isolation. Separate PostgreSQL integration tests exercise the real constraints. Destination deduplication here assumes support for stable keys; without it, ambiguous external sends require reconciliation.

    The unsafe path may repeat work three times, while the actual payment changes from PENDING to SUCCEEDED only once. Processing attempts are not successful state transitions.
