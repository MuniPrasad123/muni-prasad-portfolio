What improves when we change the thread model?

Platform threads

Request A waits for the network → its operating-system thread stays occupied. If the request pool is full, request B queues.

Virtual threads

Request A pauses during supported I/O → its carrier runs B → A resumes when the response arrives. More waiting requests can stay in progress.

This benefit needs suitable blocking I/O and spare dependency capacity. The controls above model dependency limits, not a measured virtual-thread speedup. Java 21 pinning can prevent a carrier from being freed.

Why Future.get(timeout) is insufficient

It bounds how long the caller waits, not how long remote work lasts. A cancellation request may not stop an HTTP operation or reverse an authorization. Keep local permits until the local task exits, configure transport deadlines and reconcile uncertain provider outcomes.
