03 · The actual SQL fix
Try the query on PostgreSQL 15+ with the sample schema from the full blog. Notice the tie-breaker and exclusive cursor:
CREATE INDEX idx_orders_customer_created_id
ON orders (customer_id, created_at DESC, order_id DESC)
INCLUDE (status, total_amount);

SELECT order_id, created_at, total_amount
FROM orders
WHERE customer_id = 42
  AND created_at >= TIMESTAMPTZ '2026-10-30 00:00+00'
  AND created_at < TIMESTAMPTZ '2026-11-02 00:00+00'
  AND (created_at, order_id) <
      (TIMESTAMPTZ '2026-10-31 12:00+00', 1005)
ORDER BY created_at DESC, order_id DESC
LIMIT 3;

ORDER BY created_at DESC, order_id DESC LIMIT 2;
-- Expected: 1005, 1004
Architect — Why can an INCLUDE index still read heap pages?
MVCC visibility can require heap access. Validate `Heap Fetches`, buffer reads and actual plans. For a large production rollout, assess disk/WAL and use `CREATE INDEX CONCURRENTLY` when appropriate.
