How to read this simulation

Both consumers receive identical notifications. A Kafka offset identifies a record in one topic partition; an order version identifies its business sequence. Recovery is a separate worker step, not a new Kafka record.

The tracking view begins at CREATED v1, behind the order service. A held event means tracking is checking updates; it does not mean checkout or the actual payment failed.

This is an in-memory browser model. Production needs durable waiting events, atomic database checks, and reconciliation with the order service.
